# Комфортный маршрут на велосипеде

Постройте удобные маршруты для человека на городском велосипеде.
В наборе — дороги Констанца, данные о поездках и 36 пар точек A–B.

## Установка

Нужен Python 3.11+. Клонируйте репозиторий или скачайте **Code → Download ZIP**.
Команды выполняйте из папки проекта.

```bash
git clone https://github.com/RuslanKozlyak/CycleCase.git
cd CycleCase
```

Windows (PowerShell):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\jupyter-lab.exe notebooks/hackathon_konstanz.ipynb
```

macOS / Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/jupyter-lab notebooks/hackathon_konstanz.ipynb
```

В Jupyter выберите Python из `.venv`.

## Оценка

Общая оценка — **до 100 баллов**: до 40 за автоматический рейтинг и до 60 за оценку жюри.

### Автоматический рейтинг — до 40 баллов

Рейтинг определяется **популярностью маршрутов на закрытых парах A–B**, от 0 до 100. Это пары точек начала и конца маршрута, которые жюри использует для итоговой проверки.
Внутри маршрута популярность участков усредняется с учётом длины, затем рассчитывается среднее по всем заданным парам.

Баллы начисляются относительно лучшего результата среди команд:

**Баллы = 40 × популярность команды / популярность лидера.**

Команда с лучшим результатом получает 40 баллов. При одинаковом лучшем результате все лидеры получают по 40 баллов.

## Рекомендуемая структура презентации

На презентацию отводится **7 минут**.

| Раздел | Что показать |
| --- | --- |
| **1. Идея решения** | Название команды и основная идея: как вы предлагаете выбирать подходящий маршрут для городского велосипедиста |
| **2. Исследование данных** | Какие свойства дорог вы выбрали и почему. Собственные наблюдения о данных, найденные пропуски и способы их обработки |
| **3. Метод** | Как работает алгоритм и что вы изменили. Понятная схема выбора маршрута, используемые признаки и настройки |
| **4. Общие результаты** | Сводная таблица сравнения своего решения с кратчайшим маршрутом по всем заданным парам A–B: количество построенных маршрутов, средняя длина и выбранные показатели качества. Краткий вывод: что удалось улучшить и что стало хуже |
| **5. Удачные примеры** | Маршруты, на которых решение хорошо выполняет задумку команды. Сравнение путей на карте, значимые участки и объяснение полученного результата. Можно показать пример в Санкт-Петербурге или своём городе и объяснить результат на знакомых улицах |
| **6. Неудачные или проблемные примеры** | Случаи, где решение работает хуже ожидаемого или улучшение одного показателя ухудшает другой. Возможные причины и предложения по улучшению. Можно показать пример в Санкт-Петербурге или своём городе и объяснить результат на знакомых улицах |
| **7. Выводы** | Что удалось получить, в каких условиях метод полезен, какие ограничения сохраняются и что стоит проверить дальше |

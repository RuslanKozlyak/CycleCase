# CicleGpx

Учебный проект по построению веломаршрутов по популярным улицам. Данные представлены плоской таблицей рёбер, а части,
которые участники хакатона могут менять, оформлены обычными функциями.

```text
prepare_city() -> edges, nodes -> pandas-фильтр -> check_connectivity()
                                                -> build_graph(edges, nodes, cost)
                                                -> find_route() / build_routes()
                                                -> score()
```

Популярность улиц не входит в `edges` и не попадает в маршрутный граф. Она хранится отдельно в
`popularity.parquet`. В ML-эксперименте разрешено обучение на части train; validation используется
для выбора настроек, test — для итоговой оценки. Поиск получает только рассчитанные стоимости.
`trips=NaN` означает отсутствие сопоставленного наблюдения, `trips=0` — явный ноль в источнике;
`has_observation` отмечает известные значения. Неизмеренные дороги сохраняются для маршрутизации,
но не участвуют в обучении и оценке популярности. Версия кеша 2 автоматически пересопоставляет
наблюдения старого кеша, сохраняя дороги, узлы и исходные OD.

## Публичный пайплайн

```python
from pathlib import Path

from cycle_routing import (
    COMFORT_PRESETS,
    build_graph,
    build_routes,
    filter_edges,
    is_rideable,
    load_od_pairs,
    prepare_city,
    score,
)

cache = Path("notebooks/data/cities")
edges, nodes = prepare_city("konstanz", cache_dir=cache)
edges = filter_edges(edges, is_rideable, keep_largest=True)

preset = COMFORT_PRESETS["balanced"]
graph = build_graph(edges, nodes, cost=preset["cost"])
pairs = load_od_pairs("konstanz", cache_dir=cache)
routes = build_routes(edges, nodes, pairs, COMFORT_PRESETS, cache_dir=Path("outputs/routes_cache"))
metrics = score(routes, "konstanz", cache_dir=cache)
```

На рёбрах готового графа остаются только `cost`, `length_m` и `geometry`; OSM-теги и наблюдения
остаются в таблицах.

## Точки расширения

Каждое поле решения задаётся данными (без кода) или функцией (кодом) — интерфейс один, формы смешиваются.

| Поле | Без кода | Кодом |
|---|---|---|
| фильтр `filter_edges(edges, keep)` | `drop_values(edges, колонка=[значения])` — маска без рёбер с этими значениями; маски складываются через `&` | любая pandas-маска или `keep(edges) -> Series[bool]` |
| стоимость `cost` | `{"highway": {"primary": 3.0}}` — изменения весов `DEFAULT_COMFORT_CONFIG`, или имя пресета `"quiet"` | `cost(edges) -> Series[float]` в эквивалентных метрах |
| повороты `turns` | `"none"`, `"default"`, `"min_turns"` (`TURNS`) или `{"left_penalty_m": 60}` | `penalty(graph, incoming, outgoing) -> float` |
| поиск `search` | `"dijkstra"`, `"bellman_ford"`, `"astar"` (`SEARCH`) | функция networkx как есть или своя `search(graph, source, target, weight="cost") -> [узлы]` |

Профиль — словарь `{"label", "description", "cost", "turns", "search"}`; профиль без кода — обычный JSON.
Восемь готовых профилей `COMFORT_PRESETS` устроены так же. С поворотами поиск идёт по `turn_graph`: его
узлы — рёбра улиц, а поворот — обычное ребро со штрафом.

В таблице `score` метрика `сумма поездок по рёбрам` складывает наблюдаемое число поездок по всем
пройденным рёбрам и повторно учитывает ребро, если оно используется в нескольких OD-маршрутах.
Это сумма известных измерений; если на маршрутах модели нет ни одного измерения, результат — NaN.
`score` также показывает долю длины с измерениями. Средняя популярность и доля популярных улиц
считаются по известным меткам с весом длины, без геометрического переноса счётчика с соседней дороги.

## Структура проекта

- `preparation.py` — города, загрузка OSM/наблюдений, плоские таблицы и кеш;
- `graph.py` — фильтрация, связность и сборка минимального маршрутного графа;
- `comfort.py` — векторная модель комфорта и объяснение её множителей;
- `presets.py` — восемь готовых функций стоимости;
- `routing.py` — поиск, повороты, пакетный прогон и кеш маршрутов;
- `evaluation.py` — чёрный ящик `score`;
- `visualization.py` — карты, принимающие таблицу рёбер;
- `workshop.py`, `workshop_maps.py` — API и карты ноутбука хакатона (`score`, блоки решения, экспорт);
- `workshop_data.py`, `splits.py` — подготовка наборов хакатона и подключаемое разбиение на открытую и закрытую зоны;
- `TASK.md` — задание участникам.

Старые графовые функции оставлены как адаптеры для прежних примеров и регрессионных тестов, но новый
ноутбук использует только табличный API.

## ML и проверка влияния настроек

В конце ноутбука есть отдельный эксперимент на Констанце. Градиентный бустинг предсказывает
`log(1 + trips)` по OSM-признакам. Пространственные блоки размером 1 км делятся на train,
validation и test; оба направления улицы остаются в одной части. Географическое разбиение фиксировано,
а внутри каждой части используются только сопоставленные значения, включая явный ноль.
Географическая маска не доказывает наличие измерения. `learning.py` содержит признаки и модель.

На одинаковых OD-парах сравниваются сила ML (`ML_STRENGTHS`) и вес велодорожек
(`CYCLEWAY_WEIGHTS`). Таблица показывает изменение самих путей, популярность относительно
кратчайшего, покрытие оценочными данными и объезд. Популярность — среднее `log(1 + trips)` по длине
оценённых участков, а не сумма поездок. Сила ML выбирается по validation с ограничением медианного
объезда `MAX_DETOUR_PCT`, затем один выбранный вариант проверяется на test.

Опциональный `RUN_SPB_CHECK=True` дополнительно переносит модель Констанца на личные GPX в Петербурге без
перенастройки. Используется текущая адресная пара; показатель «по вашим улицам» оценивает долю длины
на привычных улицах, а не совпадение с одной конкретной поездкой. Таблицы и график сохраняются в
`outputs/ml_popularity/`. По умолчанию этот прогон выключен: при отсутствии актуального кеша СПб
он требует загрузки OSM и не должен задерживать основной эксперимент Констанца.

## Топология OD и сравнение всех профилей

Последний раздел ноутбука показывает карту исходных 20 OD, распределение длин и направлений,
перекрытие кратчайших коридоров и покрытие наблюдениями. Затем строится отдельный диагностический
набор из 20 пар: пространственно разнесённые перекрёстки, группы длин 1,5–3 / 3–6 / 6–10 км,
четыре направления и предпочтение новых коридоров. Отбор использует географию и сеть, без поездок,
предсказаний ML и результатов пресетов. Исходный кеш OD не меняется.

На одной допустимой сети сравниваются все `MY_PRESETS`, ML с зафиксированной силой и кратчайший путь.
Таблицы содержат одинаковое пересечение покрытых OD для всех моделей в каждом наборе и срезе:
все сопоставленные измерения (описательная оценка) и отложенные test-участки с известными метками. Объезд, повороты и популярность
считаются на одном наборе пар; число пар показано явно. Дополнительно показан медианный объезд по всем
20 OD: именно он используется для рейтинга с ограничением объезда. Карта и матрицы по каждой OD показывают,
где пресеты различаются и как меняется рейтинг при смене набора. Это диагностические пары,
а не восстановленный спрос между точками. При одинаковой лучшей популярности на отдельной паре
перечисляются все совпавшие решения, без произвольного выбора одного победителя.

Код отбора и диагностики — `od_analysis.py`. CSV, карты и графики сохраняются в `outputs/od_topology/`,
интерактивная карта — `od_map.html`.

Карта сопоставленной популярности по умолчанию включает положительные значения и подтверждённые нули.
`only_observed=False` добавляет дороги без измерений серым пунктиром. Неизвестная популярность
и отсутствующие значения других числовых панелей не окрашиваются как нулевые.

# Веломаршрут: материалы хакатона

Студенты получают готовый граф Констанца, OSM-признаки, наблюдаемую популярность части улиц,
20 общих пар A–B и инструменты построения/оценки маршрутов.
Задача — повысить популярность улиц маршрута при ограниченном объезде относительно кратчайшего пути.
Констанц содержит агрегированные потоки STADTRADELN 2024, **не индивидуальные GPX**.
Совпадение с реальным маршрутом конкретной поездки здесь измерить нельзя.

## Старт студента

Распакуйте `hackathon_student.zip` в отдельный каталог, затем из его корня:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\jupyter-lab.exe notebooks/hackathon_konstanz.ipynb
```

Установка зависимостей требует интернет. Подготовленные данные и карта без OSM-подложки работают локально.
Выберите ядро созданного окружения и выполните **Run All**. Ноутбук также запускается из основного репозитория.
Данные загружаются через `load_lab()`: эта функция ничего не скачивает и не пересобирает.
Для HTML-карт в заново открытом ноутбуке может понадобиться стандартная команда Jupyter **Trust Notebook**.

## Что менять

В ноутбуке 31 ячейка, из них 16 с кодом. Точки настройки выделены прямо в тексте:

| Ручка | Как использовать |
|---|---|
| Дорожные приоритеты | `priority_cost(traffic=…, rough=…, cycling=…, unlit=…, narrow=…)` |
| Собственная формула | `cost(roads) -> pd.Series`, индекс как у `roads`, конечные положительные значения |
| Признаки | `features(roads)` и `feature_catalog()`; исходные OSM-теги тоже доступны |
| Повороты | `None`, готовый режим, словарь штрафов или функция `penalty(graph, incoming, outgoing)` |
| Поиск | `dijkstra`, `astar`, `bellman_ford` или функция с интерфейсом NetworkX |
| ML | Обучение на `lab.training_data()`; `learned_cost(model, strength=…)` переводит прогноз в стоимость |
| Сравнение | `compare(lab, solutions)`; единый протокол для готовых пресетов, формул и ML |
| Разбор поведения | `route_diagnostics(lab, result)`, `result.per_od`, `route_explorer(lab, result)` |
| Сдача | `export_solution(...)`, сохранённый ноутбук и короткое объяснение решения |

`workshop.py` содержит учебный интерфейс, `workshop_maps.py` — визуализации,
`learning.py` — пример ML. Поиск и повороты находятся в `routing.py`.
Можно пользоваться готовыми функциями, а затем постепенно заменять их своими.

Стоимость рёбер и штрафы за повороты имеют общую условную шкалу: при изменении масштаба стоимости
меняется относительная сила штрафов. Для контролируемого эксперимента меняйте один фактор за раз.

## Данные и пропуски

Учебный набор содержит 38 333 направленных ребра, 15 068 узлов и 20 OD.
Оставлена наибольшая сильно связная компонента в географической зоне наблюдений.
Это выбранный район, а не весь исходный регион обоих берегов озера.
OD детерминированно покрывают географию, длины, направления и разные коридоры.
Они не представляют распределение фактического спроса.

* `edges.parquet`: ключ `(u, v, key)`, `length_m`, метрическая геометрия EPSG:25832 и OSM-теги.
* `nodes.parquet`: узлы с метрическими координатами; `pairs.parquet`: неизменный банк A–B.
* `partition.parquet`: пространственная часть каждой дороги, включая дороги без измерений.
* `labels_train.parquet`, `labels_validation.parquet`: **только известные** количества поездок с ключами рёбер.
* `manifest.json`: версия, идентификатор и SHA-256 файлов; `load_lab()` проверяет целостность.

Вырезанные по маске зоны наблюдений дороги всё равно могут не иметь сопоставленного количества поездок.
Известный ноль сохраняется нулём. Отсутствие строки с меткой означает **NaN**, а не нулевую популярность.
Неизмеренные рёбра остаются в графе, но исключаются из обучения и среднего по популярности.
На карте режим поездок окрашивает доступные измерения; серый пунктир означает неизвестное значение.

Готовые признаки — простые эвристики по OSM, а не измеренный комфорт.
`speed_kmh`, `lanes`, `width_m` по умолчанию равны 30, 1 и 3; рядом есть флаги `_missing`.
Отсутствие тега велоинфраструктуры/покрытия/освещения не доказывает отсутствие свойства.
Граф учитывает направление дорог и базовую допустимость велосипеда, но не OSM-отношения запретов поворота.

## Единая оценка

Это предложенная учебная шкала, **не процент точности GPX**:

1. Для маршрута считаем `L = sum(length * log(1 + trips)) / sum(length)` на известных метках выбранной части.
2. Для каждой OD считаем `delta = L_solution - L_shortest`. `exp(delta)` — отношение геометрических средних `(1 + trips)`.
3. Официальный банк оценки заранее образуют OD, у которых **кратчайший** имеет покрытие хотя бы 10% длины.
   Этот список не зависит от добавленных решений. Для validation и test он может различаться.
4. Балл OD — `100 / (1 + exp(-delta))`. Кратчайший имеет 50 баллов.
   Нет пути, покрытие решения <10% или объезд >20% **на этой OD** → 0 баллов.
5. Итог — среднее баллов по фиксированному банку. Дополнительно показываем популярность, медианный/p90 объезд,
   покрытие и количество зачтённых OD. Высокая популярность при большом объезде не гарантирует высокий балл.

Train/validation/test разделены пространственными блоками порядка 1 км: примерно 60/20/20% блоков,
а не ровно такие доли рёбер или известных меток. Обратные/параллельные направления одной улицы не разделяются.
Границы блоков не устраняют всю пространственную зависимость.
Учиться можно на train, выбирать настройки — по validation. Test хранится у организатора отдельно.
Покрытие 10% — мягкий диагностический порог: результат при редких измерениях остаётся ограниченным свидетельством.
Для другого мероприятия можно **до начала соревнования** выбрать более строгий порог и зафиксировать его для всех.
Нельзя выбирать OD или менять правила после просмотра результатов команды.

## Организатору: подготовка и итоговая проверка

Следующие команды выполняются в основном репозитории организатора.
Они не нужны для студенческого запуска готового ZIP.

```powershell
.\.venv\Scripts\python.exe tools/prepare_hackathon_data.py --warm-presets
.\.venv\Scripts\python.exe tools/package_hackathon.py
.\.venv\Scripts\python.exe tools/grade_hackathon.py outputs/hackathon_demo/submission
```

Подготовка использует мастер-кеш `notebooks/data/cities/konstanz` и его исходные наблюдения.
Если их нет, прежний `prepare_city()` может скачать исходники.
Учебный набор пишется в `notebooks/data/hackathon/konstanz`,
закрытые метки — в `outputs/hackathon_private/konstanz`.
Преподавательский проверяющий код проверяет идентификатор набора, связность представленного пути и его концы,
пересчитывает длину по исходным рёбрам, строит собственный shortest и применяет общие правила.
Для участников архив не содержит закрытых меток, исходного мастер-кеша или личных GPX.
`tools/build_hackathon_notebook.py` восстанавливает чистый шаблон; после него ноутбук нужно заново выполнить.

## Дополнительно: Петербург

Личные GPX не включаются в студенческий ZIP. Для локальной проверки организатор может подготовить отдельный набор:

```powershell
.\.venv\Scripts\python.exe tools/prepare_hackathon_data.py --spb-graph ПУТЬ_К_ЛОКАЛЬНОМУ_GRAPHML
```

Команда использует явно указанный граф и GPX из `cicle_gpx/`, сохраняя происхождение графа в манифесте.
В ноутбуке включите `RUN_SPB = True`. Формула и ML переносятся с Констанца без переобучения.
Это дополнительная проверка на одном личном наборе и фиксированной адресной OD, без отдельного теста холодного сезона.
Популярность GPX получена пространственным сопоставлением посещений с дорогами;
ошибки GPS и сопоставления ограничивают точность этой проверки.

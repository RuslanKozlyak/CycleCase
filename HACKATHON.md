# Веломаршрут: материалы хакатона

Команды строят маршруты A–B по дорожной сети Констанца так, чтобы они шли по популярным у велосипедистов
улицам и не были сильно длиннее кратчайшего пути. Популярность улиц — агрегированные потоки STADTRADELN 2024,
**не индивидуальные GPX**: совпадение с конкретной поездкой здесь измерить нельзя.

## Старт студента

Распакуйте `hackathon_student.zip` в отдельный каталог, затем из его корня:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\jupyter-lab.exe notebooks/hackathon_konstanz.ipynb
```

Установка зависимостей требует интернет, дальше всё работает локально. Выполните **Run All**.
Для HTML-карты в заново открытом ноутбуке может понадобиться **Trust Notebook**.

## Ноутбук

Разделы: данные → фильтр → тестовые пары → решение → ML → сравнение → разбор → Петербург → сдача.
Ячейки с ✏️ — места для своего кода; в каждой уже есть рабочий пример. Таблица дорог `city.roads` и все
признаки названы по-русски (`тип_дороги`, `покрытие`, `велодорожка`, …). Значения категорий в `city.roads`
тоже русские с подчёркиваниями: `пешеходная_дорожка`, `служебный_проезд`, `жилая_улица`, `асфальт`.
`data_dictionary` показывает значения, которые можно использовать прямо в фильтрах и признаках.

| Блок | Что вписать |
|---|---|
| Фильтр | `rideable(roads)` полностью показан в ячейке; `keep(roads) -> Series[bool]` использует его и добавляет свои условия |
| Признаки | `features(roads) -> DataFrame`: длина и три признака; расчёт виден в ячейке и передаётся в стоимость и свою модель |
| Веса | словарь `{признак: вес}`; стоимость = длина × (1 + Σ вес × признак) |
| Своя стоимость | необязательно: `my_cost(roads) -> Series` вместо формулы |
| Повороты | `my_turn_penalty(graph, incoming, outgoing)` явно считает угол и штраф; также можно выбрать `None` или `"min_turns"` |
| Поиск | `my_search` вызывает обычный `nx.dijkstra_path`; `greedy_search` реализован с нуля и сравнивается отдельно |
| Быстрая проверка | `preview_cost(city, my_cost)`: признаки и стоимость типичных дорог без поиска маршрутов |
| ML | готовая модель `train_popularity(city)`; прогноз — признак `ml_популярность` (0–1) с весом |
| Своя модель | `train_model(x, y)` создаёт модель, вызывает `fit` и возвращает её; `train_custom_model(city, train_model, features=features)` готовит данные и проверяет результат |

Имена в сравнении берутся из `solution["label"]`. Данные города хранятся в `CityData` (`city`),
в результатах и сети тот же объект доступен как `result.city` и `network.city`.

Исходные характеристики и признаки — разные таблицы: `city.roads → features(roads) → стоимость / ML`.
`длина_м` явно копируется из `city.roads` в `features` и служит базовым множителем стоимости, поэтому
отдельный вес ей не нужен. Добавляйте остальные признаки в ту же функцию и соответствующие веса в `WEIGHTS`.
Своя ML-модель получает все столбцы `features`, включая длину.
Пример фильтра: `drop_values(roads, тип_дороги=["пешеходная_дорожка"])`.
Несколько тегов участка сохраняются через `;`, поэтому для них используйте `has_any`.
Геометрия описана как «линия дороги; координаты в метрах».
После `my_turn_penalty` показаны четыре ситуации на реальных дорогах: прямо, плавный изгиб, разворот,
правый и левый поворот. Стрелки показывают въезд и выезд, маленький круг — направления 0–360°;
под картой — угол и штраф, вычисленный вашей функцией.

## Оценка

Одна таблица, по строке на решение и строка `кратчайший`:

| Столбец | Смысл |
|---|---|
| популярность | главный критерий, 0–100: насколько популярны улицы маршрута (70 — популярнее 70% улиц города), среднее по парам |
| популярнее кратчайшего | в скольких парах маршрут выигрывает у кратчайшего |
| объезд, % | насколько маршрут длиннее кратчайшего (медиана) |
| поворотов | среднее на маршрут |
| неудобные участки, м | лестницы, запреты для велосипеда, частные проезды на всех маршрутах |
| время поиска, мс | медианное время одного поиска пути, без построения графа |

Популярность участка — доля измеренной длины улиц с меньшим числом поездок. Участок без измерения
считается средним (50): маршрут не выигрывает, уходя на неизмеренные дороги, и не выпадает из оценки. Маршрут длиннее кратчайшего больше чем на 20% засчитывается как кратчайший,
отсутствие маршрута — как 0. Кратчайший путь всегда считается на одной и той же базовой сети
(велосипедные дороги, основная связная часть).

## Открытая и закрытая зоны

Город делится на две зоны с похожим составом (центр и пригород в обеих). Команды видят метки и пары
только открытой зоны. Итог организатор считает тем же `score` на закрытой зоне по сданному решению.

Разбиение подключаемое (`src/cycle_routing/splits.py`):

* `routes` (по умолчанию): у каждой пары есть коридор — кратчайший путь и альтернативы до +20%.
  Коридоры открытой и закрытой зоны разнесены не меньше чем на 800 м; каждая дорога относится к зоне
  ближайшего по дорогам коридора; полоса 150 м вокруг закрытой зоны остаётся без меток.
* `sectors`: шахматка квадратов 3 км; берутся пары, коридор которых лежит в одном цвете.

Пары отбираются без значений поездок: только длина (1,5–3 / 3–4,5 / 4,5–6 км), центр или пригород,
измерено не меньше 75% кратчайшего пути, есть реальная альтернатива, концы и коридоры не повторяются.
Кроме того, 8 готовых пресетов и 5 контрастных наборов весов должны давать на паре не меньше 5 разных путей
с объездом до 20% (`min_variety`): на таких парах смена настроек видна в маршруте.
В каждой группе пары добавляются по одной в обе зоны, поэтому зоны равны по составу.

## Организатору

```powershell
# набор, который сейчас в ноутбуке: 36 пар в зоне
.\.venv\Scripts\python.exe tools/prepare_hackathon_data.py --name konstanz_more --params '{"per_zone_stratum": 15, "separation_m": 600, "min_endpoint_m": 300, "max_overlap": 0.35}'
.\.venv\Scripts\python.exe tools/prepare_hackathon_data.py --split sectors    # другой вариант: набор konstanz_sectors
.\.venv\Scripts\python.exe tools/check_split.py --pack konstanz_more          # согласие рейтингов зон, карта
.\.venv\Scripts\python.exe tools/build_hackathon_notebook.py                  # чистый ноутбук команд
.\.venv\Scripts\python.exe tools/package_hackathon.py                         # студенческий ZIP с набором из ноутбука
.\.venv\Scripts\python.exe tools/verify_hackathon.py                          # прогон ZIP в изоляции
.\.venv\Scripts\python.exe tools/build_grading_notebook.py                    # ноутбук проверяющих
.\.venv\Scripts\python.exe tools/make_demo_submissions.py                     # демо-решения для пробы
```

Ноутбук выбирает набор параметром `PACK`; другое разбиение — другое имя набора. Параметры разбиения
можно передать JSON: `--params '{"separation_m": 1000}'`. Закрытые пары и метки лежат в
`outputs/hackathon_private/<набор>`, в ZIP они не попадают. `check_split.py` сравнивает рейтинг
готовых пресетов и вариантов весов в двух зонах и с согласием двух случайных половин одной зоны.

## Проверка сданных решений

Команда сдаёт папку из `export_solution` (или её ZIP). Положите сдачи в `outputs/hackathon/submissions`, по одной на
команду, и выполните `notebooks/hackathon_grading.ipynb` (тот же `PACK`, что у команд). Ноутбук показывает:

- какие решения загрузились, а какие нет и почему (нет `submission.json`, другой набор данных, ошибка в коде);
- итог: **ярус** (команды одного яруса не различаются в пределах шума закрытых пар), **популярность, закрытая зона**
  (итоговая оценка) с **±** (90% интервал), **популярность, открытая зона** для сравнения, остальные столбцы как у команд;
- карту маршрутов всех команд на закрытой зоне и баллы по каждой паре.

Загрузка решения выполняет код команды — кладите туда только решения участников. Ноутбук проверяющих читает
закрытую зону и в студенческий ZIP не попадает. То же из командной строки:
`tools/grade_hackathon.py outputs/hackathon/submissions --pack konstanz_more`.

## Проверка идей команд

`tools/try_solutions.py --pack konstanz` прогоняет около 40 решений в том виде, как их написала бы команда:
веса, свои признаки, своя стоимость, функции поворотов и поиска, своя ML-модель, и одно запрещённое решение
со стоимостью из `city.trips`. Каждое оценивается на открытой и закрытой зоне (`outputs/solution_ideas/`).
Это проверяет, что все блоки ноутбука работают со своим кодом, рейтинг открытой зоны переносится на закрытую,
а утечка меток в стоимость на закрытой зоне ничего не даёт.

## Петербург

Личные GPX в ZIP не входят. Набор готовится отдельно:

```powershell
.\.venv\Scripts\python.exe tools/prepare_hackathon_data.py --spb-graph notebooks/data/cities/saint_petersburg/<граф>.graphml
```

Берётся окрестность фиксированной адресной пары (3 км), GPX-треки — отдельным слоем карты.
В ноутбуке блок «Петербург» прокладывает решения команды без перенастройки и показывает их рядом с треками.
Локальный ноутбук требует этот набор и не пропускает блок при его отсутствии. Студенческий ZIP содержит
только Констанц: ячейки Петербурга с меткой `local-spb` исключаются при упаковке вместе с личными данными.

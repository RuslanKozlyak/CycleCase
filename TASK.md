# Задание: велосипедный маршрут по популярным улицам

Постройте маршруты A–B по дорожной сети Констанца так, чтобы они шли по улицам, где действительно ездят
велосипедисты, и были не сильно длиннее кратчайшего пути. Популярность улиц — агрегированные потоки
STADTRADELN 2024 по участкам. Целых поездок между A и B в данных нет, поэтому оценивается популярность улиц
маршрута, а не совпадение с чьим-то треком.

Работа идёт в `notebooks/hackathon_konstanz.ipynb`. Ячейки с ✏️ — ваши блоки; в каждой уже есть рабочий пример.

## Что дано

- `city.roads` — участки дорог: `длина_м`, `геометрия` и теги OSM под русскими именами (`тип_дороги`, `покрытие`,
  `ровность`, `велополоса`, `велосипед`, `освещение`, `служебный_проезд`, `доступ`, `макс_скорость`, `полос`,
  `ширина_м`, `одностороннее`). Значения категорий переведены на русский с подчёркиваниями:
  `пешеходная_дорожка`, `жилая_улица`, `асфальт`. Словарь ноутбука показывает эти же значения.
- `city.trips` — поездки по участку. `NaN` — не измерено (это не ноль), `0` — измеренный ноль.
  Метки есть только в открытой части города; итог считается на закрытой части.
- `city.pairs` — тестовые пары A–B открытой части.

## Блоки решения

1. **Фильтр** `keep(roads) -> Series[bool]`: какие дороги разрешены. Полный код `rideable(roads)` виден в ноутбуке.
   Участки, оторванные от основной связной сети, в маршрутах не используются.
2. **Признаки**: `features(roads) -> DataFrame` содержит длину и три признака. Меняйте и добавляйте их здесь.
   Длина — базовый множитель стоимости; отдельный вес ей не нужен. Своя ML-модель получает все столбцы этой таблицы.
3. **Веса**: стоимость = длина × (1 + Σ вес × признак); плюс — избегать, минус — предпочитать.
4. **Своя стоимость** (необязательно): функция `roads -> Series` с положительными значениями.
   `preview_cost(city, my_cost)` быстро покажет, как стоимость оценивает типичные дороги.
5. **Повороты**: `my_turn_penalty` считает угол по геометрии и возвращает штраф; можно менять пороги и значения.
6. **Поиск**: `my_search` с обычным Дейкстрой из NetworkX и собственный `greedy_search` со списком путей и явным циклом выбора.
7. **ML** (необязательно): прогноз популярности как признак `ml_популярность` со своим весом. Готовая модель —
   `train_popularity(city)`; своя — функция `train_model(x, y)`, которая явно вызывает `fit` и возвращает модель.
   `train_custom_model` готовит признаки, цель `log(1 + поездки)` и проверку на отложенных кварталах.

## Идеи для экспериментов

- Веса с разным «характером»: любитель велодорожек, подальше от машин, тихие жилые улицы, без грунта.
- Свои признаки: асфальт, велосипед явно разрешён, ограничение 30 км/ч, крупная улица с велополосой.
- Своя стоимость: таблица множителей по `тип_дороги` или экспонента от признаков.
- Повороты: штраф только на настоящих перекрёстках, отдельно налево и направо, `"min_turns"`.
- Поиск: Дейкстра и жадный поиск (разные стратегии), A*, самый удобный путь с объездом не больше
  заданного, выбор лучшего из нескольких кандидатов.
- ML: разная сила прогноза, своя модель (случайный лес, классификатор «популярная улица»), прогноз вместе с поворотами.

## Правила

- Фильтр, стоимость и поиск не используют `city.trips` и вообще поездки. Поездки — только для обучения ML.
- Функции получают всю таблицу и возвращают результат с тем же индексом.
- `score` не меняется: это общая оценка для всех команд.

## Оценка

| Столбец | Смысл |
|---|---|
| популярность | главный критерий, 0–100: насколько популярны улицы маршрута, среднее по парам |
| популярнее кратчайшего | в скольких парах маршрут выигрывает у кратчайшего |
| объезд, % | насколько маршрут длиннее кратчайшего |
| поворотов | среднее на маршрут |
| неудобные участки, м | лестницы, запреты для велосипеда, частные проезды |
| время поиска, мс | скорость алгоритма поиска |

Улица без измерения считается средней (50). Маршрут длиннее кратчайшего больше чем на 20% засчитывается
как кратчайший, без маршрута — как 0.

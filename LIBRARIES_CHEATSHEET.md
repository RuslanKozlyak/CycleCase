## pandas

### Таблица, столбец и индекс

`DataFrame` — таблица, `Series` — столбец с индексом. Индекс — метка строки, не обязательно её порядковый номер.

```python
import pandas as pd

roads = city.roads
display(roads.head())                         # первые 5 строк
print(roads.shape)                            # число строк и столбцов
print(roads.columns)                          # названия столбцов
print(roads.dtypes)                           # типы данных

display(roads["длина_м"])                      # Series
display(roads[["длина_м", "тип_дороги"]])       # DataFrame
display(roads.iloc[:3])                       # строки по позиции
```

`pd.DataFrame(index=roads.index)` создаёт таблицу признаков с теми же метками строк, что у дорог.
По меткам строк pandas определяет, какому участку дороги принадлежит значение.
Сохраняйте `roads.index` при создании таблицы в `features` и результата функции стоимости.

### Сравнения

Сравнение столбца с числом возвращает маску — столбец из `True` (условие выполнено) и `False` (не выполнено) для каждого участка.

| Метод | Оператор | Смысл |
|---|---|---|
| `s.ge(100)` | `s >= 100` | Больше или равно |
| `s.gt(100)` | `s > 100` | Больше |
| `s.le(100)` | `s <= 100` | Меньше или равно |
| `s.lt(100)` | `s < 100` | Меньше |
| `s.eq(100)` | `s == 100` | Равно |
| `s.ne(100)` | `s != 100` | Не равно |

```python
s = pd.Series([50, 100, 150])
print(s.ge(100).tolist())                     # [False, True, True]
display(roads.loc[roads["длина_м"] >= 100])     # участки от 100 м
```

### Маски: и, или, отрицание

| Запись | Смысл |
|---|---|
| `a & b` | Оба условия выполнены |
| `a \| b` | Выполнено хотя бы одно условие |
| `~a` | Обратить True и False |
| `mask &= extra` | То же, что `mask = mask & extra` |
| `roads.loc[mask]` | Выбрать строки с True |

```python
mask = (roads["длина_м"] >= 100) & (roads["длина_м"] <= 500)
display(roads.loc[mask, ["длина_м", "тип_дороги"]])
```

В выражениях со столбцами нужны `&`, `|`, `~` и скобки вокруг сравнений.
Python-операторы `and`, `or`, `not` предназначены для отдельных условий.

### Проверка условий: any и all

`any()` — есть хотя бы одно True, `all()` — все значения True.

```python
mask = pd.Series([False, True, False])
print(mask.any())                            # True
print(mask.all())                            # False
print(mask.sum())                            # 1: число True

checks = pd.DataFrame({"a": [True, False], "b": [False, False]})
print(checks.any(axis=1).tolist())            # [True, False]: внутри каждой строки
print(checks.any(axis=0).tolist())            # [True, False]: внутри каждого столбца
print(checks.any(axis=None))                 # True: по всей таблице
```

Без `axis` получается отдельный ответ для каждого столбца. Для одного ответа по всей таблице используйте `checks.any(axis=None)`.
У пустого столбца True/False `any()` вернёт False, а `all()` — True.

### Дорожные теги: isin и has_any

Теги — записанные характеристики дороги, например покрытие. В одной ячейке может быть несколько значений через `;`.
`isin` сравнивает ячейку целиком, а функция проекта `has_any` проверяет отдельные значения внутри неё.

```python
from cycle_routing.tags import has_any

s = pd.Series(["асфальт", "асфальт;гравий", None])
print(s.isin(["асфальт"]).tolist())           # [True, False, False]
print(has_any(s, "асфальт").tolist())         # [True, True, False]
print(has_any(s, {"асфальт", "гравий"}).tolist())  # [True, True, False]
```

`has_any` — функция проекта, не метод pandas. Названия значений берите из `data_dictionary(city)`.
Она даёт ответ для каждого участка, а `mask.any()` — один ответ: есть ли хотя бы один подходящий участок.

Пример своего признака:

```python
bike = has_any(roads["тип_дороги"], "велодорожка")
asphalt = has_any(roads["покрытие"], "асфальт")
f["велодорожка_с_асфальтом"] = (bike & asphalt).astype(int)
```

### Пропуски и числа

`NaN` — значение неизвестно или не указано. Это пропуск в данных, а не ноль.
`0` — известное значение, смысл которого зависит от столбца: например, ноль поездок.

| Приём | Для чего |
|---|---|
| `s.isna()` / `s.notna()` | Найти отсутствующие / известные значения |
| `s.fillna(0)` | Заменить пропуски нулями, если это соответствует смыслу данных |
| `s.astype(int)` | Преобразовать True/False в 1/0 |
| `s.astype(float)` | Преобразовать в числа с дробной частью |
| `pd.to_numeric(s, errors="coerce")` | Превратить строки в числа; что не удалось преобразовать → NaN |
| `s.clip(lower=0.1)` | Заменить все значения меньше 0.1 на 0.1 |
| `s.value_counts()` | Посчитать, сколько раз встречается каждое значение |
| `s.mean()` / `s.min()` / `s.max()` / `s.sum()` | Среднее, минимум, максимум, сумма |
| `s.to_numpy()` | Получить массив без индекса pandas |

В `city.trips` пропуск означает «не измерено»; заменять неизвестное число поездок нулём нельзя.

### Точки и геометрия

`city.roads` и наборы городских объектов — таблицы GeoPandas. Кроме обычных столбцов, они хранят геометрию:
у участка дороги — линию на карте, у светофора или велопарковки — точку.

```python
points = city.points
display(points_dictionary(city))             # виды городских объектов в текущем наборе
display(points["светофоры"].head())           # примеры светофоров
display(points["велопарковки"].columns)       # названия столбцов
```

Внутри `features` можно учитывать объекты рядом с дорогой:

```python
f["светофор_50м"] = within_radius(roads, points["светофоры"], 50).astype(int)
f["парковка_100м"] = within_radius(roads, points["велопарковки"], 100).astype(int)
```

`within_radius` проверяет, есть ли нужный объект в пределах заданного расстояния от любого места участка. Расстояние задаётся в метрах.
Например, `светофор_50м` показывает, есть ли светофор в пределах 50 м: после `.astype(int)` 1 — есть, 0 — нет.

### Таблица маршрутов и свои показатели качества

`result.route_table` содержит маршруты с русскими названиями столбцов:

| Столбец | Что хранит |
|---|---|
| `пара` | Обозначение пары: A — начало поездки, B — конец |
| `решение` | Название решения |
| `длина_м` | Физическая длина маршрута |
| `поворотов` | Число поворотов |
| `время_поиска_мс` | Время поиска, если оно измерено |
| `рёбра` | Последовательность участков `(u, v, key)` |
| `геометрия` | Линия маршрута |

В `(u, v, key)` указаны начало участка, конец и номер, различающий участки между теми же точками.

### Группировка: groupby и agg

```python
routes = result.route_table
routes["поворотов_на_км"] = routes["поворотов"] / (routes["длина_м"] / 1000)

comparison = result.comparison
comparison["поворотов на км"] = routes.groupby("решение")["поворотов_на_км"].mean().round(1)
display(comparison)
```

`groupby("решение")` собирает маршруты одного решения в группу, `mean()` усредняет значения внутри неё.
При усреднении каждый построенный маршрут учитывается одинаково, независимо от длины. Число построенных маршрутов показано отдельно.

Несколько операций для каждой группы:

```python
summary = routes.groupby("решение").agg(
    средняя_длина_м=("длина_м", "mean"),
    максимальная_длина_м=("длина_м", "max"),
    среднее_поворотов=("поворотов", "mean"),
)
display(summary)
```

В записи `новое_имя=("столбец", "операция")` слева задаётся имя результата, справа — что и как считать.

## NetworkX (nx)

### Граф дорожной сети

Граф строится в NetworkX (`nx`). Вершины — точки дорожной сети, рёбра — направленные участки дорог.
В `MultiDiGraph` между двумя точками может быть несколько участков, например дорога и велодорожка.
Тройка `(u, v, key)` указывает начало, конец и номер нужного участка.
Наличие пути A → B не гарантирует наличие пути B → A.

| Выражение | Результат |
|---|---|
| `node in graph` | Есть ли вершина |
| `graph.nodes[node]` | Свойства вершины, в том числе координаты `x`, `y` |
| `graph.successors(node)` | Куда можно выйти из вершины |
| `graph.predecessors(node)` | Откуда можно прийти |
| `graph.edges[u, v, key]` | Свойства конкретного участка |
| `graph.number_of_nodes()` | Число вершин |
| `graph.number_of_edges()` | Число рёбер |
| `nx.has_path(graph, source, target)` | Есть ли направленный путь |

`cost` — условная длина участка для алгоритма. `weight="cost"` означает: искать путь с наименьшей суммой этих значений.
Если стоимость равна настоящей длине, получится кратчайший путь по длине. С учётом штрафов выбранный путь может быть длиннее.
Дорожные признаки вычисляются по таблице дорог, а поиск получает уже готовые стоимости.

### Алгоритмы поиска

`G` — граф, `s` — начало, `t` — конец, `h` — функция оценки оставшейся стоимости пути.

| Алгоритм | Вызов | Что учитывает |
|---|---|---|
| Дейкстра | `nx.dijkstra_path(G, s, t, weight="cost")` | Сумму неотрицательных стоимостей |
| A* | `nx.astar_path(G, s, t, heuristic=h, weight="cost")` | Стоимость пройденного пути и оценку оставшейся стоимости |
| Беллман — Форд | `nx.bellman_ford_path(G, s, t, weight="cost")` | Допускает отрицательные стоимости; обычно медленнее |
| Двунаправленный Дейкстра | `nx.bidirectional_dijkstra(G, s, t, weight="cost")` | Возвращает `(стоимость, путь)` |
| Поиск в ширину, BFS | `nx.shortest_path(G, s, t)` | Число рёбер: длины и штрафы не учитываются |

В проекте стоимости должны быть положительными, даже если выбранный алгоритм допускает отрицательные веса.
Явно передавайте `weight="cost"`: значение по умолчанию у функций NetworkX может быть другим.

### Как подключить поиск

Функция принимает граф, начало, конец и название свойства, по которому считается стоимость (`weight`). Возвращает список вершин, включая оба конца.

```python
def my_search(graph, source, target, weight="cost"):
    return nx.dijkstra_path(graph, source, target, weight=weight)

mine = solution(my_cost, turns=my_turn_penalty, search=my_search, label="моё решение")
```

Двунаправленный Дейкстра возвращает два результата: стоимость и путь. Для подключения верните только путь:

```python
def bidirectional_search(graph, source, target, weight="cost"):
    distance, path = nx.bidirectional_dijkstra(graph, source, target, weight=weight)
    return path
```

### A* и жадный поиск

В ноутбуке `greedy_search` — собственная функция. Она выбирает продолжение ближе к цели,
не учитывает стоимость уже пройденного пути и не гарантирует путь с наименьшей стоимостью.

A* учитывает стоимость пройденного пути `g` и оценку оставшейся стоимости `h`.
Чтобы гарантировать путь с наименьшей стоимостью, `h` не должна завышать оставшуюся стоимость. Без `heuristic` используется ноль, и A* работает как Дейкстра.
Расстояние по прямой подходит не всегда: условная длина предпочтительных дорог может быть меньше настоящей.
Квадрат расстояния из `greedy_search` тоже нельзя просто перенести в A*: он может завысить оценку.

### Поиск с поворотами

`turns=my_turn_penalty` включает учёт поворотов. Для этого проект создаёт другой граф:
его вершины обозначают участки `(u, v, key)`, а переходы — движение с одного участка на другой.
Дополнительные вершины обозначают начало и конец маршрута. Стоимость перехода включает следующий участок и штраф за поворот.
Возвращайте вершины **того графа, который получила функция поиска**; они не обязательно являются целыми числами.

### Обход и связность

| Задача | Функция | Особенность |
|---|---|---|
| Обход в ширину / глубину | `nx.bfs_tree`, `nx.dfs_tree` | Находят вершины, до которых можно добраться из начальной |
| Слабая связность | `nx.weakly_connected_components` | Группы связанных точек, если не учитывать направления дорог |
| Сильная связность | `nx.strongly_connected_components` | В каждой группе из любой точки можно добраться в любую другую с учётом направлений |
| Пути от одной вершины | `nx.single_source_dijkstra` | Возвращает расстояния и пути |
| Альтернативные пути без повторов | `nx.shortest_simple_paths` | Генератор; MultiDiGraph не поддерживается |

Генератор выдаёт пути постепенно. `list(...)` запрашивает все пути, что может потребовать много времени.

## scikit-learn (sklearn)

### Что получает модель

В проекте решается задача **регрессии** — предсказания числа: сколько поездок приходится на участок дороги.

| Переменная | Содержимое |
|---|---|
| `x` | Таблица: строки — участки дорог, столбцы — числовые признаки из `features` |
| `y` | Значение, которое учится предсказывать модель для каждой строки: `log(1 + число поездок)` |
| `model` | Модель scikit-learn, которую создаёт и обучает `train_model` |
| `my_model` | Хранит обученную модель, названия признаков и функцию их расчёта `features` |

Логарифм в `y` уменьшает различия между маленькими и большими значениями числа поездок.
`train_custom_model` подготавливает `x` и `y`, проверяет модель на дорогах из кварталов, которые не использовались при её обучении (отложенных кварталах).
Затем обучает итоговую модель на всех известных открытых измерениях. Строки без измерений в обучение не попадают.

### Обучение и прогноз: fit и predict

| Вызов | Действие |
|---|---|
| `model.fit(x, y)` | Обучить модель на признаках и ответах |
| `model.predict(x_new)` | Получить прогноз для новых строк с теми же признаками |
| `model.get_params()` | Посмотреть параметры модели |
| `model.set_params(max_depth=3)` | Изменить глубину дерева; затем обучить его заново |

В ноутбуке заменяйте функцию `train_model`. Например, можно попробовать небольшое дерево:

```python
from sklearn.tree import DecisionTreeRegressor

def train_model(x, y):
    model = DecisionTreeRegressor(max_depth=2, random_state=42)
    model.fit(x, y)
    return model

my_model = train_custom_model(city, train_model, features=features)
display(my_model.predict_log_trips(city.roads).head())
```

Прогноз остаётся в той же шкале, что `y`: `log(1 + поездки)`.
После изменения модели выполните ячейки от обучения до сравнения и карты заново.

### Модели scikit-learn

| Модель | Импорт | Идея |
|---|---|---|
| `DummyRegressor` | `from sklearn.dummy import DummyRegressor` | Начальный вариант: одно и то же среднее значение `y` для любого участка |
| `Ridge` | `from sklearn.linear_model import Ridge` | Складывает признаки с весами; ограничивает слишком большие веса |
| `DecisionTreeRegressor` | `from sklearn.tree import DecisionTreeRegressor` | Делит дороги по условиям вида «признак больше порога» |
| `RandomForestRegressor` | `from sklearn.ensemble import RandomForestRegressor` | Усредняет прогнозы нескольких деревьев |

### Параметры моделей scikit-learn

| Параметр | Где используется | Что меняет |
|---|---|---|
| `strategy="mean"` | DummyRegressor | Предсказывать среднее значение `y` |
| `max_depth` | Дерево, лес | Глубина дерева: сколько последовательных вопросов об участке оно может задать |
| `min_samples_leaf` | Дерево, лес | Минимальное число обучающих строк в конечной группе |
| `n_estimators` | Лес | Число деревьев; больше деревьев требует больше времени |
| `alpha` | Ridge | Насколько сильно ограничивать веса |
| `random_state` | Дерево, лес | Позволяет повторить эксперимент с теми же случайными решениями |
| `n_jobs` | Лес | Число параллельных задач; `1` — одна, `-1` — все доступные процессоры |

Веса внутри `Ridge` модель подбирает при обучении; это отдельные веса, не `WEIGHTS` для выбора маршрута.
Сложная модель может хорошо запомнить обучающие дороги и хуже работать на новых.
Сравнивайте результаты на отложенных кварталах, а не только на обучении.

### Pipeline: подготовка признаков вместе с моделью

Для Ridge важно учитывать масштаб признаков: длина в сотнях метров и признак 0/1 имеют разный разброс.
`Pipeline` объединяет подготовку и модель в одну цепочку. Её обучение тоже выполняется через `fit`.

Другой вариант `train_model`:

```python
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import Ridge
from sklearn.pipeline import make_pipeline

def train_model(x, y):
    model = make_pipeline(
        SimpleImputer(strategy="median", keep_empty_features=True),
        StandardScaler(),
        Ridge(alpha=1.0),
    )
    model.fit(x, y)
    return model
```

- `SimpleImputer` заполняет пропуски в признаках типичными значениями — медианами обучающих данных; полностью пустой столбец сохраняет и заполняет нулём.
- `StandardScaler` приводит признаки к сопоставимому масштабу: вычитает среднее и делит на стандартное отклонение обучающего признака.
- `Ridge` учится на подготовленной таблице.

Для новых дорог цепочка использует параметры, найденные при обучении. Заполняются пропуски **признаков**, не неизвестные поездки.
Деревьям и лесу выравнивание масштаба обычно не требуется.

### Как прогноз влияет на маршрут

`ml_feature(my_model)(roads)` превращает прогноз в признак `ml_популярность` от 0 до 1.
Чем выше прогноз числа поездок относительно других переданных участков, тем ближе значение к 1.
В ноутбуке этот столбец добавляет `features_with_my_model`.

```python
ML_WEIGHTS = WEIGHTS.copy()
ML_WEIGHTS["ml_популярность"] = -0.25
my_ml_cost = comfort_cost(ML_WEIGHTS, features=features_with_my_model)
```

Отрицательный вес уменьшает условную длину участков с высоким прогнозом, поэтому алгоритм чаще их выбирает. Вес 0 отключает влияние прогноза.
Точность прогноза числа поездок и качество построенного маршрута проверяются отдельно.

## Другие библиотеки машинного обучения

| Библиотека | Для чего |
|---|---|
| XGBoost, CatBoost, LightGBM | Градиентный бустинг: модели последовательно исправляют ошибки предыдущих |
| PyTorch, TensorFlow/Keras | Нейронные сети |
| statsmodels | Статистические модели и регрессия |
| Optuna | Подбор параметров модели |

Пример обучения с CatBoost:

```python
from catboost import CatBoostRegressor

def train_model(x, y):
    model = CatBoostRegressor(
        iterations=100, depth=5, random_seed=42,
        thread_count=2, verbose=False, allow_writing_files=False,
    )
    model.fit(x, y)
    return model
```

Аналогично доступны `xgboost.XGBRegressor` и `lightgbm.LGBMRegressor`.
Обученная модель должна иметь метод `predict(x)`, возвращающий по одному прогнозу для каждой строки таблицы.

Дополнительно для PyTorch, statsmodels и Keras: результат должен быть одномерным NumPy-массивом — списком чисел без вложенных списков.
Для PyTorch и statsmodels создайте объект с методом `predict(x)`, который вызывает вашу модель.
В PyTorch используйте CPU (процессор), `eval()` и `torch.no_grad()` — режим прогноза без обучения. Прогноз Keras приведите к нужному виду через `.reshape(-1)`.
После подбора параметров в Optuna верните из `train_model` лучшую обученную модель.

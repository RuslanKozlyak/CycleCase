# Хакатон «Веломаршрут»: проделанная работа и выводы

Журнал решений по учебному ноутбуку и оценке. Инструкция для студентов и организатора — в [HACKATHON.md](HACKATHON.md),
задание — в [TASK.md](TASK.md). Презентацию не меняли.

## 1. Постановка

- В презентации главный критерий — «близость к реальному GPX-треку». В данных Констанца индивидуальных треков нет,
  есть только агрегированные потоки STADTRADELN 2024 по участкам улиц. Поэтому критерий заменён на
  **популярность улиц маршрута** при ограниченном объезде относительно кратчайшего пути.
- Участники — школьники 15–17 лет, поэтому ноутбук сделан с минимумом текста и кода, с русскими названиями.

## 2. Что было не так в прежней оценке

- Метки делились мелкими блоками ~1 км на train/validation/test. По validation-меткам маршрут был измерен
  только на 22–30% длины, и в оценку попадали лишь 10 из 20 пар.
- Баллы прыгали из-за правила «мало измерений», а не из-за популярности. Таблицы были перегружены
  (сигмоида, `reason`, `in_evaluation`, дублирующиеся столбцы).

## 3. Валидация: открытая и закрытая зоны

Команды видят метки и пары только **открытой** зоны. Итог считается тем же `score` на **закрытой** зоне по сданному решению.

Рассмотренные варианты разбиения (измерено км в зонах / доля «города»):

| вариант | итог |
|---|---|
| запад / восток по медиане | 1084 / 597 км, город 15% / 56% — «город против деревни», отклонён |
| юг / север по медиане | 534 / 1147 км, город 76% / 9% — отклонён |
| вдоль полуострова | 900 / 781 км, город 43% / 12% — перекос |
| шахматка секторов 3 км | 796 / 884 км, город 31% / 27% — сбалансировано, но маршруты пересекают границы |
| северный берег (Überlingen) как закрытая зона | 193 км против 870 — в 4,5 раза меньше, нет плотного центра |
| **коридоры пар (выбран)** | зоны режутся вокруг коридоров пар по дорожному расстоянию |

**Разбиение по коридорам** (`splits.by_routes`):
- коридор пары = кратчайший путь + альтернативы с объездом до 20%;
- коридоры открытой и закрытой зоны разнесены минимум на 800 м, в каждой группе (длина × город/пригород) пары
  добавляются по одной в обе зоны;
- каждая дорога относится к зоне ближайшего по дорогам коридора (сетевой Вороной), закрытая зона — не дальше 1 км
  от своих коридоров, полоса 150 м вокруг неё без меток;
- маршруты остаются в своей зоне: доля длины вне зоны — 0–2%, покрытие измерениями 95–99%.

Проверка согласия рейтинга пресетов и вариантов весов между зонами (`tools/check_split.py`):

| разбиение | пар в зоне | ρ открытая/закрытая | шум (две половины одной зоны) |
|---|---|---|---|
| коридоры, текущий набор | 25 | 0,82 (90% ДИ 0,64–0,92) | 0,79 |
| сектора 3 км | 17 | 0,74 (0,23–0,80) | 0,73 |

Разбиение подключаемое: `tools/prepare_hackathon_data.py --split routes|sectors --name ... --params '{...}'`,
в ноутбуке выбирается одним параметром `PACK`.

## 4. Отбор пар

Без значений поездок, только по сети и наличию измерений:
- длина 1,5–3 / 3–4,5 / 4,5–6 км, центр или пригород;
- измерено не меньше 75% кратчайшего пути, есть реальная альтернатива (штрафной метод);
- концы и коридоры не повторяются;
- **разнообразие путей**: 8 готовых пресетов и 5 контрастных наборов весов должны давать не меньше 5 разных путей с
  объездом до 20%.

Последний критерий добавлен после замечания, что на OD06/OD14 пресеты давали одинаковые пути:

| | до | после |
|---|---|---|
| `balanced`, `fast`, `min_turns` дают три разных пути | 11 из 28 пар | 21 из 25 |
| `balanced` = `fast` | 15 из 28 | 4 из 25 |
| разных путей на пару (8 пресетов + кратчайший), медиана | ~5 | 7 |

## 5. Метрика

Одна таблица, по строке на решение и строка `кратчайший`:

| столбец | смысл |
|---|---|
| популярность | главный критерий, 0–100: доля измеренной длины улиц с меньшим числом поездок, по длине маршрута, среднее по парам |
| популярнее кратчайшего | в скольких парах маршрут выигрывает у кратчайшего |
| объезд, % | медиана |
| поворотов | среднее на маршрут |
| неудобные участки, м | лестницы, запреты для велосипеда, частные проезды |
| время поиска, мс | медиана, только поиск, без построения графа |

Правила:
- **неизмеренная улица = 50** («средняя»). Раньше неизмеренные участки исключались, и решение, уводящее маршрут на
  пешеходные дорожки (измерено 21% их длины), оценивалось только по немногим измеренным кускам; маршрут без
  измерений выпадал бы из среднего;
- маршрут длиннее кратчайшего больше чем на 20% → в оценку пары идёт популярность кратчайшего;
- нет маршрута → 0;
- кратчайший всегда считается на одной базовой сети (велосипедные дороги, основная связная часть).

## 6. Ноутбук студента

`notebooks/hackathon_konstanz.ipynb` собирается скриптом `tools/build_hackathon_notebook.py`; объект данных — `city`
(`city.roads`, `city.trips`, `city.pairs`, загрузка `load_city`):

1. **Данные** — словарь столбцов (тип, значения), минимальный набор строк, в котором заполнен каждый столбец, карта
   популярности с явными слоями «нет измерения» и «тестовая зона: измерения скрыты».
2. **Фильтр ✏️** — `keep(roads)`, готовый `rideable`, карта: основная сеть / убрано / оторвано (оторванные участки
   не используются в маршрутах).
3. **Тестовые пары** — одна карта кратчайших путей.
4. **Решение ✏️** — пример целиком: готовые признаки (`feature_catalog`) → свои признаки `my_features` и сразу таблица
   участков, где они есть (`preview_features`) → веса со своими признаками и быстрая проверка `preview_cost`
   (признаки с весом, цена 1 м, стоимость последним столбцом) → своя формула на тех же признаках и её проверка →
   повороты, поиск (пример — двусторонний Дейкстра). Формула попадает в сравнение как «моя формула».
5. **ML ✏️** — готовая модель `train_popularity` (пресет) и своя модель sklearn через `train_model` (пример — дерево
   глубины 1); прогноз — признак `ml_популярность` с весом.
6. **Сравнение** — таблица из п. 5 и график.
7. **Разбор** — офлайн-карта: пара, решение, 8 режимов цвета (популярность, велоинфраструктура, тип дороги,
   покрытие, освещение, скорость машин, стоимость, отличия), флажок «Цвет дорог вокруг», сводка столбцом
   «решение / кратчайший», легенда с цветовой шкалой.
8. **Петербург** — решения без перенастройки рядом с личными GPX, таблица совпадения с ближайшей поездкой.
9. **Сдача** — `export_solution`: решение с функциями (cloudpickle) и фильтр.

Таблица дорог и признаки названы по-русски (`тип_дороги`, `покрытие`, `велодорожка`, …), значения тегов — как в OSM;
внутри библиотеки остаются OSM-имена (`city.osm`). Студентам выдаётся ZIP без выводов ноутбука и без закрытых данных.

## 7. ML

- Обучение: только измеренные участки открытой зоны, цель `log(1 + поездки)`, признаки — только OSM-теги
  (без координат, ID и поездок), градиентный бустинг, вес — длина участка. Перед итоговым обучением — проверка на
  отложенных кварталах ~1 км (корреляция около 0,6 на текущем наборе).
- В маршруте прогноз переводится в ранг 0..1 и входит в стоимость с весом.
- **Своя модель команды** — ручка ноутбука: любой объект sklearn с `fit`/`predict` (`train_model(city, модель,
  extra=my_features)`) учится на готовых и своих признаках; прогноз становится тем же признаком `ml_популярность`.
  В ноутбуке пример — заведомо слабое дерево глубины 1; готовая модель оставлена как пресет.
- **На Петербурге модель не дообучается**: применяется модель Констанца; ранг прогноза считается среди дорог Петербурга.

## 8. Петербург

- Набор вырезается коридором ±2 км вокруг адресной пары (122 тыс. участков вместо 337 тыс.).
- GPX чистится от «телепортаций»: трек режется на скачках длиннее 150 м (было 46 скачков >100 м, до 2,9 км);
  19 поездок → 51 линия, ложные посещения улиц ушли (4 200 → 3 867 посещённых участков).
- Совпадение с ближайшей поездкой (доля длины маршрута в пределах 30 м): кратчайший 59%, «моё + ML» 32%,
  «моё» 31% — личные поездки ближе всего к кратчайшему пути.

## 9. Граф OSM и тротуары

Граф — OSMnx `network_type="all"` с упрощением; одна строка — одно направленное ребро. Тротуары и велодорожки,
нарисованные отдельными линиями, дают параллельные пути: из 675 км пешеходных дорожек и троп около 220 км идут
вдоль проезжей части (≤12 м), велосипед явно разрешён только на 37% из них. Фильтр `rideable` их не убирает.
**Решение не принято**: можно убрать фильтром или штрафовать весом `пешеходная`.

## 11. Разнообразие и различимость решений

`tools/check_distinctness.py`:
- маршруты разнообразны: в медиане 19 разных путей на пару из 38 решений; общая доля длины между решениями в среднем 0,42;
- практически одинаковы только «без штрафов», «двусторонний Дейкстра», «A*» — одна стоимость, точный поиск;
- различимость ограничена числом пар:

| | открытая | закрытая |
|---|---|---|
| пар решений, которые можно различить (90% ДИ) | 56% | 69% |
| полуширина ДИ разницы, медиана | ±3,1 | ±3,9 |
| решений надёжно лучше кратчайшего | 28 из 37 | 25 из 37 |
| ярусов неразличимых решений | 6 | 8 |

Вывод: при 25 парах разница меньше ~4 баллов — шум; первые пять решений на закрытой зоне в одном ярусе.

### Эксперимент: больше пар

Ослаблены ограничения отбора: `konstanz_more` — до 15 пар на группу, зазор между зонами 600 м, концы ≥300 м,
перекрытие коридоров ≤35%; `konstanz_more_b` — до 20 на группу, зазор 500 м, концы ≥250 м, перекрытие ≤40%,
порог разнообразия 4. Те же 37 решений + кратчайший.

| набор | пар в зоне | ДИ разницы, закр. / откр. | различимых пар решений, закр. / откр. | ярусов, закр. / откр. | ρ рейтинга зон | лучше кратчайшего (закр.) | измерено в своей зоне (закр.) | открытых меток |
|---|---|---|---|---|---|---|---|---|
| `konstanz` (текущий) | 25 | ±3,9 / ±3,1 | 69% / 56% | 8 / 6 | 0,84 | 25 из 37 | 96,3% | 12 997 |
| `konstanz_more` | 36 | ±2,7 / ±2,8 | 66% / 62% | 6 / 6 | **0,90** | 30 из 37 | 96,5% | 9 447 |
| `konstanz_more_b` | 43 | ±2,6 / ±2,5 | 60% / 73% | 6 / 7 | 0,86 | 30 из 37 | 97,5% | 11 827 |

Выводы:
- больше пар сужает интервалы на закрытой зоне с ±3,9 до ±2,7 (36 пар) и ±2,6 (43 пары); различимы разницы от ~3 баллов;
- ослабленный зазор 500–600 м не привёл к протеканию: маршруты закрытых пар по-прежнему на 96–97% в измеренной
  части своей зоны;
- доля различимых пар решений не растёт сама по себе: на новых парах решения ближе друг к другу (в `_b` порог
  разнообразия ниже, минимум 4 разных пути на пару против 7);
- лучший компромисс — `konstanz_more`: интервал ±2,7, лучшее согласие рейтинга зон (0,90), порог разнообразия
  сохранён. Цена — меньше открытых меток для обучения ML (9,4 тыс. против 13 тыс.);
- `konstanz_more_b` почти не сужает интервал по сравнению с `konstanz_more`, но снижает разнообразие пар.

По итогам ноутбук команд переключён на `konstanz_more` (`PACK = "konstanz_more"`, 36 пар в зоне); набор `konstanz`
(25 пар) сохранён. Упаковка ZIP берёт набор из `PACK` ноутбука.

## 12. Ноутбук проверяющих

`notebooks/hackathon_grading.ipynb` (собирается `tools/build_grading_notebook.py`, модуль `cycle_routing.grading`):
сдачи команд (папки из `export_solution` или их ZIP) кладутся в `outputs/hackathon/submissions`, ноутбук выдаёт:

1. список сдач со статусом: загружено / нет `submission.json` / другой набор данных / ошибка в коде;
2. итог на закрытой зоне: **ярус** (команды одного яруса не различаются в пределах шума пар), популярность, **±**

## 15. Упрощение и раскрытие учебного кода — 29 октября 2026

- Прочитаны исходники и сохранённые результаты трёх ноутбуков, Markdown проекта, отчёты и история graphify.
- `comfort_routing.ipynb` перенесён в `notebooks/_to delete/`; определение корня проекта работает после переноса.
- В `data_dictionary` все значения текущих наборов Констанца и Петербурга подписаны по-русски с кодами OSM
  в скобках. Коды в таблицах сохранены для фильтров, моделей и сопоставления с исходными тегами.
- В ячейках показаны расчёт `base_features`, устройство `feature_catalog`, штрафы `my_turn_penalty` по углу,
  обычный Дейкстра и самостоятельный `greedy_search`. Жадный поиск добавлен в сравнение отдельным решением.
  В графе поворотов есть координаты конца участка, чтобы жадный поиск работал и со штрафами.
- `WEIGHTS` записан по одному ключу на строку. Изменения `base_features` используются стоимостью и своей ML-моделью.
